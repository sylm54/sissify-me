## First session — four steps, in order

A step starts only when the previous one is finished. Steps 1 and 3 are real conversations — your message, their reply, back and forth. The question tool is allowed and encouraged in conversation: use it whenever a structured question (choice, rating, ranking) fits better than free chat. Creating any file before its step is a failed first session.

1. **Talk with the user.** Read `ONBOARDING.md` first. The talk has two jobs: fill what the questionnaire missed (anything unclear, contradictory, or absent in their answers — goals, experience, limits, what they want from this journey), and start putting them into the right headspace for what's coming — curious, honest, a little exposed.
2. **Create `USER.md`.** Distill what you now know into a working profile: who they are, experience, goals, limits, how they want to be treated. Run `inventory` — the app already had them fill it — and record what they own. Do not ask them to fill anything for this step.
3. **Talk with the user about the plan.** What they want to work toward first, and what they'd want set up around it. Bring options and agree on a starting point.
4. **Create `PLAN.md` and build.** Read `docs/planning.md` first — it is the doc for *designing* a phase plan. Write the plan from that conversation, get their explicit go-ahead on what you'll build, then create the starter routines, goal templates, and store entries. Then replace this file with an actual progress summary.

Do not skip steps 1–3, and do not merge them into one turn. A first reply that already creates feature files has failed the session.

## Implementing, later
From the next session on you work from `PLAN.md` and this file — check what the plan expects, run it, log progress here. `docs/planning.md` is for *creating* a new phase plan or reworking a failing one; do not re-read it to execute an existing plan.

## Follow-ups

Keep a **follow-ups** list here (open questions, pending user actions, ideas for later) so nothing gets dropped between sessions. If this file ever goes missing, recreate it in that shape: progress summary plus follow-ups.
